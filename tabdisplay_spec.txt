Build "TabDisplay", a zero-cost, ultra-low-latency wired USB extended touchscreen display suite pairing an Apple Silicon Mac (macOS 13+) with a Lenovo Tab M10 (Android 10, Micro-USB 2.0) at exact 1:1 native landscape pixel resolution.

5 DECISION POINTS & VERIFICATION GATES
====================================================================

- DP 1: Project Scaffolding, Device Probe & Real CGVirtualDisplay Mac Virtual Monitor
  - Build:
    1. Create directory structure (`mac_host/Sources/CVirtualDisplay/include`, `mac_host/Sources/TabDisplayHost`, `android_client/app/src/main/java/com/tabdisplay/client`, `android_client/app/src/main/res/layout`).
    2. Create `tabdisplay.py` with `--probe --json` that detects `swift`, `adb`, `java`, `gradle`, `ANDROID_HOME`, connected ADB device serials, and normalized landscape resolution via `adb shell wm size` (`width > height`, defaulting cleanly to `1280x800` if no device is attached).
    3. Create `mac_host/Package.swift` (macOS 13+, linking `CoreGraphics`, `ScreenCaptureKit`, `VideoToolbox`, `CoreMedia`, `CoreVideo`, `ApplicationServices`), `CGVirtualDisplayPrivate.h`, `shim.m` (using `<objc/message.h>` runtime `objc_msgSend` to instantiate real `CGVirtualDisplayDescriptor`, `CGVirtualDisplayMode`, `CGVirtualDisplaySettings`, and `CGVirtualDisplay` and retain the display handle), `VirtualDisplayManager.swift`, and `main.swift` supporting `--self-test-display --width <W> --height <H> --fps 60 [--hidpi]`.
  - Verification (`verify_dp1.py`):
    - Run `python3 tabdisplay.py --probe --json` and assert valid JSON with `swift`, `adb`, `width > height`.
    - Compile `mac_host` using `CLANG_MODULE_CACHE_PATH=/tmp/clang-module-cache swift build -c release --package-path mac_host`.
    - Run `mac_host/.build/release/TabDisplayHost --self-test-display --width 1280 --height 800 --fps 60` and assert exit 0, `active=true` in `CGGetActiveDisplayList`, `bounds=1280x800`, and `displayID != 12345`.

- DP 2: Real GPU Frame Capture (ScreenCaptureKit) & Zero-Latency H.264 Encoder (VideoToolbox)
  - Build:
    1. Implement `ScreenCaptureEncoder.swift` attaching `SCStream` directly to the `CGDirectDisplayID` (`kCVPixelFormatType_420YpCbCr8BiPlanarVideoRange`, 60 FPS, `queueDepth = 2`, `showsCursor = true`) and encoding frames with `VTCompressionSession` H.264 High Profile (`RealTime = true`, `AllowFrameReordering = false`, `MaxKeyFrameInterval = 60`, configurable bitrate defaulting to `20000000`).
    2. Convert AVCC length-prefixed samples into Annex-B (`0x00 0x00 0x00 0x01` start codes), prepending SPS (`0x67`) and PPS (`0x68`) NAL units before every IDR (`0x65`) keyframe, and expose `requestKeyFrame()` using `kVTEncodeFrameOptionKey_ForceKeyFrame`.
    3. Wire `--self-test-encode <seconds> --width <W> --height <H> --fps 60 --bitrate <B>` in `main.swift` to capture real frames from the newly created virtual display and print total frames encoded, detected NAL unit types (`0x67`, `0x68`, `0x65`), total bytes, and average hardware encode time in ms/frame.
  - Verification (`verify_dp2.py`):
    - Build `mac_host` in release mode (`CLANG_MODULE_CACHE_PATH=/tmp/clang-module-cache swift build -c release --package-path mac_host`).
    - Run `TabDisplayHost --self-test-encode 2 --width 1280 --height 800 --fps 60 --bitrate 20000000` and assert exit 0, `>= 80` real frames captured/encoded, presence of `0x67`, `0x68`, and `0x65` NAL units, `> 10000` encoded bytes, and average hardware encode time `< 10.0` ms/frame.

- DP 3: Android 10 Client App (Fullscreen SurfaceView, localabstract Socket Server & Hardware MediaCodec)
  - Build:
    1. Create standalone Gradle + Kotlin project in `android_client/` (`compileSdk 30`, `minSdk 26`, `targetSdk 29`, Kotlin Gradle plugin, using `ANDROID_HOME` or `$HOME/Library/Android/sdk`).
    2. Implement `MainActivity.kt` (sticky immersive fullscreen, `FLAG_KEEP_SCREEN_ON`, locked `sensorLandscape`, full-bleed `SurfaceView`), `UsbSocketServer.kt` (`LocalServerSocket("tabdisplay")` reading 12-byte big-endian frame headers + Annex-B H.264 payloads with reusable buffers), `HardwareVideoDecoder.kt` (`MediaCodec.createDecoderByType("video/avc")` outputting directly to `SurfaceView.holder.surface`, configuring Qualcomm low-latency keys `vendor.qti-ext-dec-low-latency.enable=1` and `low-latency=1` safely inside `try/catch`, feeding SPS/PPS with `BUFFER_FLAG_CODEC_CONFIG` and rendering immediately with `releaseOutputBuffer(idx, true)`), and `TouchForwarder.kt` (`OnTouchListener` normalizing coordinates `[0.0, 1.0]` and flushing 9-byte binary packets for `DOWN`, `MOVE`, `UP`, two-finger `SCROLL`, and long-press `RIGHT_CLICK` on a high-priority thread).
  - Verification (`verify_dp3.py`):
    - Compile `android_client/app/build/outputs/apk/debug/app-debug.apk` using `GRADLE_USER_HOME=/tmp/gradle-user-home gradle assembleDebug -p android_client` and assert APK exists and is `> 100000` bytes.
    - Check `adb devices`; if an authorized device is attached, install via `adb install -r`, launch `com.tabdisplay.client/.MainActivity`, and assert `adb shell pidof com.tabdisplay.client` is non-empty and `adb logcat -d` confirms `localabstract:tabdisplay` is listening.

- DP 4: Wired USB Video Bridge (adb forward + TCP_NODELAY Live Streaming)
  - Build:
    1. Implement `USBBridgeClient.swift` connecting to `127.0.0.1:<port>` with `TCP_NODELAY = 1` and `SO_NOSIGPIPE = 1`, framing each encoded Annex-B access unit with the 12-byte big-endian header (`uint32` length + `uint64` monotonic nanoseconds), triggering `encoder.requestKeyFrame()` immediately on connect, and reading incoming 9-byte uplink packets on a concurrent receive loop.
    2. Wire `VirtualDisplayManager`, `ScreenCaptureEncoder`, and `USBBridgeClient` together in `main.swift` for live bridge mode (`TabDisplayHost --width <W> --height <H> --fps 60 --bitrate 20000000 --port 5555`).
  - Verification (`verify_dp4.py`):
    - Start a local Python mock TCP server on an ephemeral port, launch `TabDisplayHost --width 1280 --height 800 --fps 60 --port <ephemeral_port>` for 2.5 seconds, and assert valid 12-byte big-endian headers, valid `0x00 0x00 0x00 0x01` Annex-B start codes with SPS/PPS/IDR NAL units, and `> 40` FPS streaming throughput.
    - If an authorized ADB device is attached, also verify `adb forward tcp:5555 localabstract:tabdisplay` succeeds cleanly.

- DP 5: Bidirectional Touchscreen Injection, Auto-Reconnect Launcher & Documentation
  - Build:
    1. Implement `TouchInjector.swift` decoding the 9-byte uplink packets (`0x01` DOWN, `0x02` MOVE, `0x03` UP, `0x04` SCROLL, `0x05` RIGHT_CLICK), mapping normalized `(x, y)` coordinates onto `CGDisplayBounds(virtualDisplayID)`, and posting `CGEvent` mouse/drag/scroll events; wire it into `USBBridgeClient.swift`.
    2. Complete `tabdisplay.py` with full CLI flags (`--width`, `--height`, `--fps`, `--bitrate`, `--port`, `--hidpi`, `--dry-run`), automatic tablet resolution detection, `adb forward` setup, launching `com.tabdisplay.client/.MainActivity`, supervising `TabDisplayHost`, and an auto-reconnect watchdog loop if the USB cable disconnects/reconnects.
    3. Write comprehensive `README.md` covering USB File Transfer (MTP) + USB Debugging setup, macOS Screen Recording & Accessibility permissions, build steps, and CLI usage.
  - Verification (`verify_dp5.py`):
    - Run a local TCP test sending 9-byte `DOWN`, `MOVE`, `UP`, `SCROLL`, and `RIGHT_CLICK` packets into `TabDisplayHost` while running and assert zero errors and `< 5.0` ms round-trip handling.
    - Run `python3 tabdisplay.py --dry-run` and assert exit code 0 and valid launch plan output.
    - Assert `README.md` exists (`> 40` lines) and documents Screen Recording, Accessibility, and `tabdisplay.py` usage.
